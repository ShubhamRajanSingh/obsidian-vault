# Vault instructions for Hermes

## Existing conventions
- Read `Knowledge/_Vault Guide.md` first. Its rules take precedence over this file.

## Layout
- `Knowledge/DSA/` — DSA topics; notes live in `Knowledge/DSA/Notes/`.
- `Knowledge/System Design/` — system design notes.
- `Inbox/` — quick captures from chat. Create it if missing. One note per capture.
- `Daily/` — daily notes named `YYYY-MM-DD.md`. Create the folder if missing.
- New areas beyond DSA and system design: ask me where they should go before creating a new top-level folder.

## Writing notes
- File name = note title in Title Case, e.g. `Segment Tree.md`. No IDs or dates in topic note names.
- Some older notes have Notion export IDs in their names (e.g. `... 10466e6a92c9....md`). Leave those names as they are.
- Before creating a note, search the vault for an existing note on the same topic and add to it instead of duplicating.
- Link related notes with `[[Note Name]]` wiki links.
- Code examples in Java, in fenced code blocks.
- When editing an existing note, add or append; don't rewrite sections I wrote unless I ask.

## Never touch
- `.obsidian/` and `.git/`.
